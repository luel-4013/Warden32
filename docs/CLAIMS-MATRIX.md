# Claims matrix

Maps the paper-level claims this repository can support to their evidence in
the code and tests, plus the strength of that evidence. Strength vocabulary:

- **demonstrated in simulation** — an engine path plus a green test asserts the
  behavior in this repository (`npm test`, vitest 5.0.5; 17 files, 144 tests;
  engine version `0.3.0`, `src/storage/project.ts:7`).
- **derived from cited documentation** — the behavior encodes facts documented
  from recorded upstream sources (see `docs/VERIFIED-FACTS.md`), but has not
  been measured on hardware by this repository.
- **assumption requiring hardware validation** — numeric or behavioral
  assumptions that must be confirmed on real hardware with the procedures in
  `docs/HARDWARE-CHECKLIST.md`.

Every row cites real files. Numbers carry their provenance tags.

## Literature citations named in the spec but not yet mappable

Spec §16 names a critical review of Gupta 2017 and Flores Eslava 2023 and use
of GASET / Rzepka / Mazhar citations. In this repository only Mazhar & Shafiq
(IoTDI 2020) has code-level traceability, as the `paper` provenance on
archetype traffic shapes (`src/engine/traffic.ts`, `src/registry/devices.ts`).
The other citations have no corresponding implementation, experiment or test
evidence in-repo, so this matrix deliberately contains no rows for them; they
should be added only when experiments exist to support them.
